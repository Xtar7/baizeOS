# 后端设计问题与优化建议

## 一、路由注册问题（严重）

**状态：✅ 已修复**

**改动文件：** `backend/app/api/v1/eb_list.py`

## 二、HTTP 方法语义问题（中等）

### 2.1 DELETE + JSON body 兼容性

**状态：✅ 已修复**

**修复：** 所有涉及 DELETE 的接口增加 `methods=["DELETE", "POST"]` 双协议支持，优先从 URL 参数获取（DELETE 友好），无参数时回退到 JSON body。

**改动文件：**
- `backend/app/api/v1/kb/kb_delete.py` — DELETE/POST 双协议
- `backend/app/api/v1/tmp/tmp_delete.py` — POST/DELETE 双协议
- `backend/app/api/v1/tmp/tmp_list.py` — GET/POST 双协议

---

## 三、数据一致性与安全性问题（严重）

### 3.1 KB 删除时不清理向量索引

**状态：✅ 已修复**

**修复：**
1. 删除前校验 `kb_meta.json` 是否存在，确保只删除自己的东西
2. 统一 `settings.py` 中 `KB_DIR` 和 `KB_ROOT` 为单一常量 `KB_ROOT`
3. 更新 `index_manager.py` 引用 `KB_ROOT` 而非 `KB_DIR`

**改动文件：**
- `backend/app/services/kb_service.py` — delete() 增加完整性校验
- `backend/app/config/settings.py` — 删除 KB_DIR 常量
- `backend/app/rag/index_manager.py` — 引用改为 KB_ROOT

### 3.2 临时文件删除误删

**状态：✅ 已修复**

**修复：** 不再使用 `rglob` 模糊搜索文件名，改为通过 `chat_id` 目录作为安全边界，逐层精确查找 `{chat_dir}/{ext}/{tmp_file_id}{ext}`。

**改动文件：** `backend/app/services/tmp_service.py`

### 3.3 知识库元数据并发不安全

**状态：✅ 已修复**

**修复：** 引入 `threading.Lock` 细粒度锁，按 `kb_id` 分配锁，保护所有「读-改-写」操作（`update`, `save_file`, `delete_file`, `batch_delete_files`）。读操作（`get`, `list`）不加锁。

**改动文件：** `backend/app/services/kb_service.py`

---

## 四、错误处理与健壮性问题（中等）

### 4.1 上传后文件不存在时崩溃 + 4.3 上传无大小限制

**状态：✅ 已修复**

**修复：**
1. 上传接口前置 `request.content_length` 校验（413 拒绝超大文件）
2. `upload_service.save_and_index()` 增加 `save_path.exists()` 检查
3. 增加文件大小校验 `validate_size()`
4. 新增 `FileNotFoundError` 异常处理

**改动文件：**
- `backend/app/api/v1/kb/kb_upload.py` — 前置 content_length 校验
- `backend/app/services/upload_service.py` — 增加存在性 + 大小校验
- `backend/app/services/file_validator.py`（新增）— FileValidator 类

### 4.2 reindex 清空向量目录异常处理

**状态：✅ 已修复**

**修复：** 区分文件和目录分别处理（`is_file()` / `is_dir()`），增加 `PermissionError` 单独捕获。

**改动文件：** `backend/app/api/v1/kb/kb_reindex.py`
